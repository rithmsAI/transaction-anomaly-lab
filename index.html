A model has to earn
its complexity.

The objective is useful investigation, not an impressive model label. A baseline makes the tradeoff visible; independent calibration and held-out evaluation keep the comparison accountable.

01 / TRAIN

Fit on training only.

Isolation Forest learns from 6,000 fictional events without anomaly labels. Log-transformed features compress heavy tails. Rules are fixed before evaluation.

02 / CALIBRATE

Set a review threshold.

Scores from 2,000 separate calibration events determine an approximate review budget. Calibration labels and test outcomes do not select the threshold.

03 / EVALUATE

Count the consequences.

A held-out set of 3,000 events measures ranking quality, anomalies found, false alarms and misses. Synthetic labels appear only in evaluation.

How much review
can you afford?

Change the calibration budget to compare actual held-out outcomes. The threshold stays frozen when applied to test data, so the final alert rate can differ from the requested budget.

Evaluation that looks
past accuracy.

Calling every event normal achieves 96.3% accuracy in the seed-42 test set while finding zero anomalies. Average precision, precision/recall and false-alarm counts tell a more useful story.

Rare-event metrics

Average precision measures ranking quality across thresholds. AP lift references class prevalence. ROC-AUC is secondary; it can obscure an impractical review burden.

Paired uncertainty

Five disjoint seed triplets repeat the experiment. Paired stratified bootstrap intervals compare rankings on the same resampled rows, conditional on the fitted model and class mix.

Leakage checks

Tests verify training-only fitting and confirm that changing test labels cannot change calibration thresholds. Current iid synthetic events have no timestamps or customer histories.

Engineering beyond
the notebook.

The repository includes a local scoring service and audit-storage demo. Their purpose is to demonstrate dependable behavior under invalid input, retries, restarts and persistence failure.

Typed, authenticated API

Strict input contracts reject malformed and nonfinite features. Scoring requires an API key. Missing configuration fails startup; storage failure returns an unavailable response.

SQL audit & safe retries

Parameterized statements record decisions. Repeated event IDs return the same result; conflicting payloads are rejected. Explicit connection closure prevents leaked database handles.

Tested behavior

Tests cover concurrent retries, persistence across restarts, metric validity, leakage checks and read-only SQL filtering. The API is documented for local use, not exposed through this site.

Unusual does not mean fraudulent. This intentionally simple simulator shares assumptions with the rules baseline. A real-data extension requires appropriate licensing, decision-time features, chronological validation, label-maturity gaps and explicit customer-history handling.
